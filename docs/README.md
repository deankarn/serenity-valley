# Talks

The talks behind the `dev-harness` skills, in reading order. Each builds on the ones before it.

| # | Talk | Read it for |
|---|---|---|
| 01 | [Everything's a Box in a Box](01-everything-is-a-box-in-a-box.md) | Decomposing systems into boxes with contracts, pitching them at the right altitude, and testing each box against its own contract. |
| 02 | [The Failure Path Is an Arrow](02-the-failure-path-is-an-arrow.md) | Contracting the error path: one error type per box, retry advice carried by errors, where retries belong, and never nesting them. |
| 03 | [Clean Code](03-clean-code.md) | Everyday conventions: naming (`get` vs `find`, letting the container say it, booleans as questions), types (distinct types for IDs and units), functions (arguments ordered by variance, no flag arguments, early returns), comments that say why, and formatting you never think about again. Grows over time. |
